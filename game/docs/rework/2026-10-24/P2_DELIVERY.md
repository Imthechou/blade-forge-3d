## 二、关键发现：根因不是材质参数，是环境

### 实测链条（每步都可复现）

```
① 镜面参数（rough 0.10 / metal 0.98 / env 1.55）下画面仍像"粉灰塑料"
② 查 environment.hdr：
     亮度均值 0.1408，**91.4% 像素 < 0.19** → 暗棚
③ 拉高 envMapIntensity 到 3.5：
     高光占比 6.1% → 84.3%
     但**对比σ 从 0.1009 跌到 0.0787**；全开更跌到 0.0655
     → 整体发白，是过曝，不是金属
```

**根因**：金属的 diffuse ≈ 0，画面里几乎全是环境反射。
环境是均匀暗棚 → 反射是均匀暗灰 → 只有色调映射把暗部抬成灰 → 塑料感。
**拉强度只是把这片灰提亮，永远提不出「高光点」。**

### 解法：换成程序化摄影棚

暗底（0.010–0.038）+ 5 个**小面积高亮光源**（峰值 90–180，真 HDR 值）：

```
位置              尺寸                强度    作用
左上柔光箱      0.075×0.100         120     主高光
左上热点        0.030×0.040         180     镜面焦点
右侧窄条灯      0.020×0.240         110     第二组高光（金属关键特征）
顶部轮廓光      0.260×0.022          90     刃口/刀背亮线
地面反光        0.400×0.090           1.2    下缘不死的黑
```

实测对比（同一材质 metal0.95 / rough0.22 / env1.10 / exp0.90）：

| 指标 | 旧 HDR 暗棚 | 程序化棚 | 变化 |
|---|---|---|---|
| 对比σ | 0.1035 | **0.1719** | **+66.1%** |
| 暗区% | 0.1 | **5.1** | 金属的深邃感 |
| 高光% | 4.4 | **14.7** | 有形状、不过曝 |

生成成本 **52.7ms**（一次性，与 HDR 并行完成）。

## 四、我错了 4 次方向（全部记录）

这一节比结论更重要 —— 每次错都是「指标达标但视觉不过」：

### 错误 1：以为加纹理就能变金属

看法：CS2 靠多层贴图合成，那我也加贴图层。
做法：新建 `normalAtlas.js`，贴图高度权重给到 **68%**。
结果：S9 的刀身变成**编织布纹**。
根因：`hTexMid` 是 ±1 归一化的，×0.68 后高度摆动过大 → 法线导数**翻折** → 一格一格的亮暗面。

### 错误 2：以为格纹来自贴图层

做法：写隔离脚本，逐层关闭（贴图 / 烘焙纹样 / 法线）。
结果：**两层全关格纹仍在**（自相关峰 0.0447 → 0.0409，只降 14%）。
教训：我的自相关指标测的是**刀身波浪几何**，不是纹理 —— 指标选错了。

### 错误 3：把 `relief` 当主旋钮

做法：反复调 `uV2Surf.x`（0.64 → 0.34 → 0.07 → 0.015）。
结果：阈值扫描显示 **relief 0.07 → 0 时亮度只从 0.486 变 0.492**，这个旋钮在低值区几乎不起作用。
真相：我还写了个数学错误 —— 用了**两条互相垂直的正弦**（`sin(x)` + `sin(y)`），
      叠加就是网格 → 格子纹。改成单方向高频细丝后才消失。

### 错误 4：以为要加，其实要减

关键证据：`isolate3` 的「全关」截图（贴图/纹样/法线全关）是**最干净好看的金属**。
真相：模型**自带一套 1024² 的深色木纹贴图**（已导出确认，`shots/maphunt/model-map.png`），
      它已经提供了大量表面图案。再叠任何层都只会把它推得更脏。
修正：relief 整体系到 **0.015–0.095**（比最初小 4–7 倍），
      贴图层 0.75 → **0.18**，同时把 envMapIntensity 拉到 1.41。

**最终方向：金属感 = 干净表面 + 强环境反射。纹理只该"在高光里隐约可见"。**

### 顺带修掉的真实 bug

1. **棚环境没进生产**：`studioEnv` 只被测试脚本动态 import，bootstrap 早期 `globalThis.K3D.studioEnv` 还是 `undefined` → 静默回退旧 HDR（实测「棚=N」贯穿 9 个阶段）。改成**静态 import** 后修复。
2. **模板字符串被反引号截断**：我在 GLSL 注释里用了反引号 → 字符串提前结束 → 报 `h is not defined`、页面起不来。**同一错误犯了 3 次**，现已在注释里写明禁止。

## 五、未达成（如实记录）

1. **没有真正跨过 CS2 的门槛**。这轮做到的是「干净金属 + 有层次的反射」，
   而 CS2 的层次来自 albedo / normal / roughness / mask **四层真实贴图合成**。
   我用的是「模型自带 map + 程序化高度图 + 单层 pattern」，仍属程序化上限。
2. **S1–S4 未重构**。它们走 `uV2Preserve=1` 分支，只做染色，刀身那套 PBR 链基本不参与。
   这才是 `MATERIAL_PLAN.md` 里的 **P3**。
3. **Pattern 仍是单通道**（P4）。
4. **Wear 仍只做整体衰减**（P5）。
5. **移动端未验证**：全部是桌面 GPU + 视口模拟，无真机帧率/发热/内存采样。

## 六、下一步建议

按 `MATERIAL_PLAN.md` 的顺序，**P3（S1–S4 过程模型专属曲线）** 是收益最大的下一步 ——
现在这四阶段的观感完全取决于模型资产本身，材质系统没参与。

如果目标仍是「接近 CS2」，那么迟早要面对一个决定：
**是否引入外部 PBR 贴图资产**（normal / roughness / mask 各若干张）。
纯程序化已经到极限了 —— 这轮 4 次试错反复证明了这一点。
