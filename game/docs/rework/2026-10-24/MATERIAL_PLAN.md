> 版本 1.0 · 2026-10-24
> 目标：向 CS2 高级刀皮的材质表现靠拢，同时保持「选卡即时预览」与流畅度。
>
> 本文件是**方案**，不是完成报告。第 1 节是已经做完并实测过的，

## 0. 一页总结

### 现在走到哪了

改造前，刀身的材质系统有三层（工艺算子 / 阶段权重 / 分层叠加），
但**这三层里有 7 个关键参数是坏的或不通的**。就像一台音响接了七根线，
其中七根全没插上 —— 你能拧面板上的旋钮，但听不到任何变化。

本轮把这 7 根线接好了，并逐项实测验证。

### 离 CS2 还差什么

CS2 刀皮的质感来自**多层真实贴图合成**：

```
albedo（底色纹理）+ pattern（花纹遮罩）+ roughness（粗糙度分布）
+ normal（表面凹凸）+ wear（磨损三段式遮罩）+ HDR 环境反射
```

我们目前只有：

```
程序化底色 + 9 槽花纹图集 + 单张 S3 灰度图 + 程序化法线扰动 + 单段磨损衰减
```

**缺的是"真实贴图层"**。这是最核心的一步，也是改造的下一阶段。

### 要做什么

分 6 个阶段推进，每个阶段都能独立验收、独立回退：

| 阶段 | 内容 | 预计收益 | 风险 |
|---|---|---|---|
| P1 | 骨架修复（**已完成**） | 让所有旋钮真的能拧 | 已完成并验证 |
| P2 | 真实法线贴图层 | 跨过"程序化 vs 真实贴图"的门槛 | 中 |
| P3 | S1–S4 过程模型专属曲线 | 原料/熔液/胚体不再像石头 | 低 |
| P4 | Pattern 多层合成分层 | 卡面差异一眼可辨 | 中 |
| P5 | 磨损三段式遮罩 | 有"用过的刀"的真实感 | 低 |
| P6 | 性能与移动端 | 真机可用 | 需真机 |

## 1. 基线：P1 已完成（7 处真实缺陷）

### 1.1 核心发现

`material.js` 的 hook 系统一直有 `normalFragment` 注入点，
**柄部（bladeViewer.js）一直在用**，但 `v2/programFamilies.js` **一次都没写过它**。

后果：刀面只有几何解析法线。颜色、粗糙度、色带再怎么调，表面永远是平的
—— 这就是「像贴纸而不是金属」的根因。

### 1.2 七项修复清单

| # | 问题 | 实测证据 | 修复方式 |
|---|---|---|---|
| 1 | **刀身完全没有表面结构层** | `normalFragment` 在 v2 中出现 0 次；柄部有 | 新增 `surfaceDetail.js`，用纹样场屏幕空间导数推真实法线扰动 |
| 2 | **卡间强度梯度全被顶死** | 卡数据 `fx.y` = 0.774–1.163，shader 里 `clamp(fx.y, 0, 0.52)` 把每张卡都压成 0.52 | 映射到 0.46–0.58，均值保持 0.52 |
| 3 | **S9 调校零效果** | `k3dApplyTune(` 调用数 = 0；`uTune.*` 引用数 = 0；而 S9_12/17/20/22/23/24 六张卡确实带 tune 数据 | 补相位环（与 S6 回火同构，只用已有槽位） |
| 4 | **各向异性是死 uniform** | `uBladeAnisotropy` 只写不读；`material.js` 里 `anisotropy` 出现 **0 次** | 三源接线（材质表 / 纹理 `uTexParam6[3]` / 工艺语义 F03·F11） |
| 5 | **表面曲线与工序语义反了** | 初版只按工艺查表 → S3 锻打 0.12（最细）、S9 精校 0.48（最粗） | 改「阶段曲线为主 + 工艺乘性调制」→ S3 **0.639 最深**、S9 **0.177 最细** |
| 6 | **环境反射全程只降不升** | `scene.environmentIntensity` 0.55→1.50 亮度变化 **0.0%**；`material.envMapIntensity` 0.9→1.5 亮度 **+32.5%** | 给 `envMapIntensity` 加阶段递进 0.82→1.30 |
| 7 | **我自己写了一处错误并被抓出** | 法线 `bumped = abs(det)*normal - grad*scale`，`abs(det)≈1e-5` 被单位向量 `normal` 淹没；放大系数改 50 倍仍 **0.0%** 变化 | **先归一化 `bumped` 再混合** |

## 2. 差距分析：为什么还不是 CS2

### 2.1 五条硬差距

| # | 差距 | 现状 | CS2 的做法 |
|---|---|---|---|
| D1 | **没有真实贴图** | 全靠程序化数学算表面；仓库里 **0 张 normal map** | albedo / normal / roughness / mask 四层真实贴图合成 |
| D2 | **S1–S4 不参与刀身材质** | 走 `uV2Preserve=1`「保留模型自带贴图」分支，只做染色 | 同一套 PBR 体系覆盖全程 |
| D3 | **Pattern 是单通道** | 9 槽烘焙图集 + 单张 S3 灰度图 | 种子驱动 + 多层 mask 叠加 |
| D4 | **Wear 只做整体衰减** | 单一 `uWearLevels` 线性衰减 | 三段式遮罩：先磨边缘 → 表面失纹 → 露底材 |
| D5 | **刀身偏暗** | 本局抽到 M08 锻黑钢 `#5c564c` + S2 低纯净度卡压暗 env，`lumMean 0.24–0.33` | 明亮金属反射（exposure + 强反射 + 高光层次） |

> **关于 D5 的说明**：这不是 bug。M08 本来就是深色钢，S2 抽到低纯净度卡
> 按设计就该压暗（`envIntensity −0.22`）。但**观感上**离 CS2 的明亮金属仍有距离，
> 需要在全局光照配比上做一次针对性调整。

## 3. 改造方案

### P2：真实法线贴图层（核心，跨门槛的一步）

**目标**：让刀面拥有真正的贴图级凹凸，而不是每像素算一次正弦。

**做法（二选一，推荐 A）**

**方案 A：运行时 canvas 生成可平铺法线图（零二进制资产）**

```
1. 新建 src/render/v2/normalAtlas.js
   · 用 canvas 生成 4–6 张 512×512 可平铺 normal map
   · 三类：锻打锤痕 / 拉丝丝路 / 淬火晶粒
   · 从已有纹样场（bakedMotif 的 JS 复刻）派生高度图 → Sobel 转法线
   · 一次性生成，进纹理缓存（key = 类型 id），不参与换卡热路径
2. material.normalMap = 对应图；normalScale 由阶段曲线驱动
3. 与现有程序化法线扰动**叠加**（贴图给大结构，程序化给细节）
```

优点：不增加包体、不动构建、可离线调参。
代价：首屏多约 20–40ms 生成 4 张图（可放进现有 GPU 预热窗口）。

**方案 B：预烘焙 PNG 资产**

优点：质量上限更高。代价：增加约 1–2MB 包体，需外部工具链。

**验收**
- `material.normalMap` 非空，`normalScale` 随阶段变化
- A/B：关闭 normalMap，高频能量下降 ≥15%
- 切卡 p95 不劣于当前 25.4ms

---

### P3：S1–S4 过程模型专属曲线

**目标**：原料石、钢液、胚体现在看起来像"石头"，要像"金属在加工中"。

**现状根因**：`uV2Preserve=1` 分支只做

```glsl
col = mix(tinted, col, clamp(uSkinTexStrength*0.22 + ..., 0.22, 0.62));
col *= mix(1.0, 0.72 + 0.56*tl, 0.55);
```

即"模型贴图染色 + 亮度微调"，刀身那套 PBR 链（工艺/阶段/磨损）基本不参与。

**做法**

```
1. 区分「过程模型」与「成刀」两条材质曲线
   · 过程模型：保留模型贴图，但**接入**阶段权重、法线层、各向异性
   · 成刀：走现有完整链
2. S1 原料：提高法线强度 + 降低 metalness（矿石是半金属）
3. S2 熔炼：加"钢液流动"——用 uEffectTime 驱动的低频法线动画
   （参考 three 的 lava shader，但只用 1–2 层，不引入 fbm 循环）
4. S3 锻打：锤痕法线 + 方向性各向异性（这一阶段的主角）
5. S4 定型：锤痕被压平，法线强度下降，几何轮廓成为主角
```

**验收**
- S1–S4 各阶段 `hlEnergy` 提升 ≥20%
- S2 的刀身亮度随时间有可见波动（钢液流动）
- 过程模型不再出现"石头质感"

---

### P4：Pattern 多层合成分层

**目标**：同阶段内不同卡一眼可辨（当前 S4/S5/S7 对比σ 只有 0.09–0.10）。

**做法**

```
1. 现有：9 槽图集（每槽 1 张灰度图）+ 单张 S3 图
2. 扩展：每槽再加一层「第二遮罩」
   · layerA = 现有图集采样
   · layerB = 同图集旋转 90°/45° 再采一次
   · 混合权重由 fx.w（rank 色相）与 seed 决定 → 每张卡组合不同
3. 保持"换卡只刷 uniform、不换源码"的纪律
```

**验收**
- 同阶段 3 张卡的刀身像素 hash 互不相同
- 同阶段卡间对比σ 从 0.09 提升到 ≥0.12
- 冷启动不增加（不新增函数，只多一次 texture2D）

---

### P5：磨损三段式遮罩

**目标**：从"整体变暗"变成"边缘先磨 → 表面失纹 → 露底材"。

**现状**：`uWearLevels` 四个分量线性混到颜色上，缺少空间结构。

**做法**

```glsl
// 复用已经存在的 vEdge / vBladeEdge / vS3PlanarFace
float edgeW  = uWearLevels.x * smoothstep(0.55, 0.95, vEdge);      // 刃口优先
float surfW  = uWearLevels.y * (1.0 - k3dPatX);                    // 纹路高处先磨
float baseW  = uWearLevels.z * smoothstep(0.3, 0.8, wearNoise);    // 露底材
```

**验收**
- wear=0.2 / 0.5 / 0.8 三档的磨损区域面积单调递增
- 磨损处 metalness/roughness 与本体有明显差异

---

### P6：性能与移动端

**目标**：P2–P5 全部落地后，真机仍可玩。

**做法**

```
1. 纹理预算：normal map 总数 ≤6 张，总显存 ≤24MB（512² RGBA）
2. 程序变体守护：任何新增宏都必须过 FEATURE_FLOOR 口径（不翻转）
3. 移动端降级：检测 DPR / GPU 档位 → 关闭第二层 pattern、降低 normal 分辨率
4. 真机采样：帧率 / 发热 / 内存（需实际设备）
```

**验收**
- 桌面：选卡 p95 ≤30ms，空闲 ≥120 FPS
- 移动端（真机）：≥30 FPS，无热降频导致的持续掉帧

## 4. 技术架构：统一材质系统

### 4.1 分层职责（保持现有三层，不推倒重来）

```
┌─ 参数层（JS）─────────────────────────────────────┐
│ state.js        → 材质/纹理/工艺/磨损 → uniform 包 │
│ finishRecipe.js → 12 工艺 → 固定算子参数            │
│ surfaceDetail.js→ 阶段曲线 + 工艺调制 → uV2Surf    │  ← P1 新增
└───────────────────────────────────────────────────┘
┌─ 装配层（GLSL 注入）──────────────────────────────┐
│ programFamilies.js → map / roughness / metalness   │
│                    → physical / normalFragment     │  ← P1 接通
│ material.js        → hook 注册 + program 缓存      │
└───────────────────────────────────────────────────┘
┌─ three.js 原生 PBR ───────────────────────────────┐
│ envMap(PMREM) / clearcoat / iridescence /          │
│ anisotropy / transmission                          │  ← P1 接通 anisotropy
└───────────────────────────────────────────────────┘
```

### 4.2 三条硬纪律

1. **换卡只刷 uniform，不换源码**
   签名只允许含「源码结构」相关的选项。卡 id / 纹理 id / 工艺 id / seed 一律不进签名。
   违反它就会退回到「换一张卡重链接一次」（历史实测 S5 3.8s / S8 4.4s）。

2. **宏开关钉死在 FEATURE_FLOOR**
   `clearcoat` / `iridescence` / `anisotropy` 从 0 变正值会改 `USE_*` 宏 = 换 program。
   一律用 `Math.max(FEATURE_FLOOR, value)`，1e-4 低于 8bit 量化步长，逐像素无差异。

3. **改 GLSL 必须 bump `FAMILY_VERSION`**
   否则 three 的 program cache key 不变，同会话内会复用上一版 program。

### 4.3 阶段 × 加工序的累积模型

```
最终材质 = 基础材质（M01–M25）
         × 纹理（T01–T24，可选）
         ＋ 工艺算子（F01–F12，固定算子表）
         ＋ Σ 阶段效果（S1–S9，逐槽累积，已到达才生效）
         ＋ 磨损 / 刃线 / 稀有度（随流程单向累加）
```

关键：**阶段效果是累加的**，S5 看到的刀包含 S1–S4 的全部痕迹。
这由 `uCardFx[i].y > 0.001` 逐槽判断，未到达的槽不参与。

### 5.2 严格 A/B 测量装置（P1 已建立）

前几轮我吃过三次测量方法的亏，现在固定成纪律：

```
① canvas 是 alpha:true → 必须先铺白底再 drawImage（否则透明被读成黑）
② v2 uniform 在 material.userData.__k3dHooks，不在 material.uniforms
③ 必须冻结 uEffectTime（12 帧动画纹理会让两次测量不同）
④ 只统计刀身像素（L<0.965），背景不参与
⑤ 先做「同状态测两次」的可重复性校验，再往下比
⑥ 高频能量（|Laplacian|）比亮度均值更能反映表面结构
```

脚本：`_ab3.mjs`（严格 A/B）、`_amp.mjs`（放大系数扫描）、
`_relief3.mjs`（曲线语义校验）、`_lightab.mjs`（光照杠杆）、`_aniso2.mjs`（各向异性）。

## 6. 风险与退路

| 风险 | 影响 | 退路 |
|---|---|---|
| 运行时生成 normal map 太慢 | 首屏变慢 | 降分辨率到 256²；或移入预热窗口；或退到方案 B |
| 纹理显存超预算 | 移动端 OOM | normal map 总数 ≤6；移动端降级到 2 张 |
| P4 多层 pattern 增加编译 | 首卡卡顿 | 只用 texture2D 不新增函数；实测冷启动 |
| 移动端真机不达标 | 无法交付移动 | 现有降级路径（2D 模式）仍可用；如实标注未验 |
| 观感仍达不到 CS2 | 用户不满意 | 明确"程序化上限"，讨论是否引入外部资产工具链 |

**每一阶段都可独立回退**：所有改动都通过 uniform 或独立函数，
不改玩法、不改存档、不改启动方式。最坏情况把 `FAMILY_VERSION` 降回并禁用新 uniform。
