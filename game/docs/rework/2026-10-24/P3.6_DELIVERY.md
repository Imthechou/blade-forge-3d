## 三、S2 弧形条纹：根因与修复

### 症状

S2 熔炼（`molten_sphere_small`）球体下部有一组**规则的扇形弧形条纹**。

### 隔离过程（`_p3s2.mjs`，逐层关开关 + 自然比例小图）

| 关掉的层 | 条纹 | 结论 |
|---|---|---|
| 模型贴图 → 1×1 白 | 仍在 | 不是模型自带图案 |
| 贴图对比调制 `texGate` | 仍在 | — |
| 高度图集 `uV2SurfTile.w` | 仍在 | 不是表面高度图 |
| 钢液流动 `uV2Proc.y` | 仍在 | 不是 sin 时间波 |
| **`relief`（`uV2Surf.x`）→ 0** | **消失** | normalFragment 入口短路 |
| **微脊 `aniso`（`uV2Surf.y`）→ 0** | **明显减弱** | **主因在这一层** |
| 全关 | 消失（只剩模型棱面） | 确认是材质系统，不是几何 |

### 根因

```
hRidge = sin( vBladeLocal.y * ridgeFreq )     ridgeFreq ≈ 886
```

S2 是个**球体**。球体底极附近 UV 收敛，`vBladeLocal.y` 的变化率极大，
886 的固定频率在那里严重 undersample → **扇形摩尔纹**。

**而且物理上就不该有**：钢液表面张力让它光滑且各向同性，
根本不该有方向性微脊。P3 时给 `aniso × 0.60` 是错的（当时只想"别太平"）。

### 修复

```js
// surfaceDetail.js  surfaceParamsOf()
else if ( stageIdx === 1 ) {
  aniso = 0.0;      // 原来是 aniso * 0.60
}
```

### 验证

- 视觉：扇形条纹消失，呈斑驳熔融金属感（`shots/p3look/S2.jpg`）
- 数值：σ 0.2466，与修复前 0.2477 基本持平（没有牺牲对比度）

## 四、S4 高级卡光晕重做

### 改前是什么样

**根本没有光晕。** 两层原因，缺一不可：

1. `STAGE_CFG` 里 S4 的第 4 分量（辉光权重）**一直是 0**
2. v2 走通用算子 `k3dV2Stage`，**不调用** legacy 的 `k3dStageFx4`
   —— 所以改 `cardEffects.js` 对 v2 完全无效（我第一次就改错了地方）

改前 S4 只有一条沿长轴（`cfg.z = 1`）的平坦色带，共 24 张卡。

### 改后：三层叠加

| 层 | 手段 | 作用 |
|---|---|---|
| ① 刃口锋线 | `smoothstep(0.38, 0.92, vBladeEdge)` | 真实刃线上的窄亮边 |
| ② 大范围轮廓 | `pow(k3dFres, 1.15)` | 掠射角包边，从边缘向面内淡出 |
| ③ 沿轴扫光 + 呼吸 | `sin(vBladeLocal.x*9 - t)` | 仅 epic 以上动态 |

档位梯度按 `uCardTier`（**本卡**稀有档，不是整局最高档）：

```
rare(2)   静态锋线 + 弱 halo
epic(3)   出现扫光
legend(4) 扫光 + 呼吸
mythic(5) 全强度动态
```

**覆盖范围**：S4 共 24 张卡，其中 **12 张**（K13–K24，rare 及以上）会亮光晕；
12 张 common/fine 保持静态 —— 这是刻意的，「高级」必须真的高级。

### 关键转折：光晕必须走自发光

第一版把光晕写进 `diffuseColor.rgb`，数字涨了但**肉眼看不出来**。
诊断（固定 tier=5，只扫 S4 槽强度）：

| strength | rimLift |
|---|---|
| 0.3 | 0.0800 |
| 0.9 | 0.0849 |
| 1.8 | 0.0869 |
| 3.5 | 0.0869 ← 饱和 |

根因：**S4 的 `uBladeMetalness ≈ 0.83`，漫反射只剩 17%**。
往 albedo 里加的光被这 17% 削掉九成。

改成写 `totalEmissiveRadiance`（three 里**直接相加**，不乘 `1-metalness`）：

| 版本 | rimLift (tier1→tier5) | Δ | hiPct (tier5) |
|---|---|---|---|
| 改前 | 0.0773 → 0.0773 | 0 | 2.48% |
| albedo 版 | 0.0773 → 0.1141 | +0.0368 | 2.74% |
| **自发光版（当前）** | **0.0773 → 0.1696** | **+0.0923** | **4.94%** |

### 验证

`_s4glow.mjs` 扫 tier 1–5，出图 `shots/s4glow/tier-{1..5}.jpg`。
tier-1 无光晕、tier-5 有明显冷色包边，肉眼可辨。

## 五、这轮我又错了 4 次（全部记录）

### 5.1 「条纹度」指标再次失效

我在 `_p3s2.mjs` 里造了个 `stripeShare`（横向梯度按行累加，看前 10% 行占比）。
结果：**所有档位都显示"无关"，peaks 恒为 0**，
甚至关掉任何一层后 stripe 数值反而**上升**。

这与 P3.5 的 `axisPeakShare` 是同一类失败：
**统计量抓不到"规则条纹"这种视觉特征**。
最后仍然靠看图才定位。

> 结论：视觉缺陷的定位，**隔离开关 + 看图**是可靠的；
> 我编的"缺陷指标"到目前为止 0/3 有用。

### 5.2 环境变量解析 bug（多跑三轮无效测试）

```js
process.env.S4_STRENGTHS || ''  →  ''   // 变量未设
''.split(',')                   →  [''] 
Number('')                      →  0
isFinite(0)                     →  true
// → STRENGTHS = [0]，永远走强度分支，档位扫描永远跑不到
```

修法：`.split(',').map(s => s.trim()).filter(Boolean).map(Number)`。

### 5.3 猜错了「崩溃原因」

S1/S5 全部 `empty frame` 时，我先猜是"在 physicalFragment 里调
`k3dRegionW`/`k3dSkinW` 导致编译失败"，还据此改了一版代码。

**猜错了。** 真正的 GLSL 报错（`_glslerr.mjs` 抓到）是：

```
ERROR: 0:434: 'k3dS4RimAmt' : undeclared identifier
ERROR: 0:434: 'k3dS4SoftAmt' : undeclared identifier
ERROR: 0:434: 'k3dS4W' : undeclared identifier
ERROR: 0:435: 'totalEmissiveRadiance' : syntax error
```

而且报错上下文第 439 行**就在调用 `k3dRegionW`** —— 它完全可用。
真正原因是那三个全局的声明被注释吃掉了（见 5.4）。

> 教训：`pageerror` 为空 **不等于**没错误。
> GLSL 编译失败是**静默**的，必须用 `_glslerr.mjs` 抓原始 info log。

### 5.4 装饰性注释吃掉了代码

我在 GLSL 注释里用了 `═══ ★★` 等 Unicode 装饰字符。编译后的源码里出现：

```
412: float k3dS4W = 0.0;   // 刀身权重…vec3  k3dS4Tint = vec3( 1.0 );
```

`vec3 k3dS4Tint` 被前一行 `//` 注释吞掉 —— 换行在某个环节丢失，
导致后面的变量全部 undeclared。

同类现象在文件别处也有（L424 的 `uniform vec4 uS3UV;` 也被吞）。

**修法：GLSL 模板字符串里的注释一律用纯 ASCII，不用装饰性框线字符。**
已写进 `V2_UNIFORMS` 的注释里提醒后来者。

## 七、未达成 / 仍存疑

1. **光晕的档位单调性有回落**：tier-3 的 rimLift（0.1861）高于 tier-4（0.1848）、
   tier-5（0.1696），但 hiPct 是单调上升的（3.56→4.04→4.27→4.94）。
   原因是 tier 越高 `sweep` 的动态幅度越大，某一时刻的轮廓区亮度会波动。
   **是否需要修成严格单调，取决于你想要"稳"还是"活"**，我没擅自决定。

2. **只看了 S4 的 knife_kris 一个刀型**。24 张卡里其他刀型
   （蝴蝶刀/爪子刀/骷髅匕首）的刃口掩码分布不同，光晕表现可能有差异。

3. **`_p3s2.mjs` 的 stripeShare 指标无用**，保留仅作留档，不要引用它的结论。

4. **移动真机仍未测**（继承 P2/T15 缺口）。
