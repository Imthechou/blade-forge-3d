#### 试玩发现并已修复的问题（5 个真实缺陷）

##### 1) 【严重·回归】鉴定页六维被裁断且整页不能滚

- **玩家看到**：鉴定页只显示「强度/韧性/锋利/工艺」四行就被切掉，**设计与灵性看不到**，

- **量化**：`.ap-body` 的 `clientHeight=309`，`scrollHeight=2437`，但 `overflow-y: hidden`。
- **根因**：我在 T13.3 把主链揭晓（六维→特性→倍率→总分）从可滚动的 `.ap-panels`
  搬进了 `.ap-body`，而 `.ap-body` 默认 `overflow: hidden`，只有 `@media (max-height:680px)`
  才切成 `overflow-y: auto`。视口 844px 不触发该断点 → 内容被裁且无法滚动。
- **修复**：`.ap-body` 默认即纵向滚动容器，不再依赖屏高（`css/pages/appraise.css`）。
- **复验**：滚到六维段落，6 项全部进入视口（（截图已移除）），
  总分 231/253 与共用收藏卡均可达。

##### 2) 【中】决策卡「标签补档」行被省略号截断

- **玩家看到**：卡片底部只显示「稳态 0→1 层 · …」，**「补到哪一档」这个关键信息被截掉**，
  而 T14 明确要求卡片表达「补到哪档标签」。
- **量化**：`.dcard-tier` 可用宽 94px，文本需 152px，`nowrap + ellipsis` 直接吃掉后半。
- **修复**：改为最多两行（`-webkit-line-clamp: 2`），保留完整语义。
- **复验**：94/94 完整显示，S5 截图中可见「热相 0→1 层 · 补到工艺倾向」两行完整。

##### 3) 【中】S4 升档 toast 与舞台提示叠印

- **玩家看到**：打出升档时，「强化达到第 1 档」和「点击此区域挥锤·无需瞄准」
  **两层文字压在一起**，两行都读不清。
- **量化**：toast 垂直 385–422、cue 386–421，`overlapY=35 / overlapX=116`（完全重叠）。
  成因：toast 在手机上固定 `bottom: calc(50dvh + safe-b)`，正好落在舞台底部热区提示上。
- **修复**：升档回执改为写进 S4 自己的 HUD 状态行，不再用覆盖舞台的 toast。
- **复验**：`toast.rect = null`，cue 保留且无重叠。

##### 4) 【轻】S4 同一句操作说明重复出现两次

#### 顺带纠正的两个「假问题」

试玩首轮报过两个 ERR/WARN，**查明是我的脚本缺陷，不是产品问题**，已修正脚本：

1. **「新手引导挡住鉴定页」**：引导由 `bootstrap.js:288` 的 `setTimeout(…, 360)` 延迟触发，
   实测在 reload 后 **2397ms** 才出现；脚本固定 400ms 检查与它赛跑。
   改为轮询 + 每次截图前兜底关闭。
2. **「揭晓链断裂（只出现 top）」**：脚本按 **60 帧**采样，本机 180Hz → 仅约 330ms，
   而六维在 660ms 才揭晓。改为按**墙钟**采样 4s 后，顺序完整正确。

> 教训：帧数不等于时间；模态层要先关掉再判断页面内容。

#### 仍建议后续关注的体验点（未改）

1. **S5 淬火配色偏艳**：`渐染色层` 预览呈高饱和粉紫，与「金属层次」调性有落差。
   属美术取向，本轮未调整（不属缺陷）。
2. **切页均约 156ms**：主要来自 3D 舞台重挂载与资源准备，未优化。
3. **真机未测**：本轮为桌面 Chrome + 手机视口，真机 GPU/散热/内存未覆盖。

## 五、开发交接

更新：2026-10-24。先读 [架构与定位指南](ARCHITECTURE.md) 与 [验收](VALIDATION.md)。

用户已要求将设定差距整理成交给 pi agent 的改造任务，见 [玩法与体验改造执行文档](archive/REWORK_PLAN_2026-10-24.md)。它定义下一阶段实施范围，尚未代表玩法改造完成；当前工程变更状态仍以下文和验证记录为准。

#### 当前入口

- 玩家：上一级“开始游戏.cmd”（唯一入口，已内联 Node 检测 + 启动），自动开服并打开浏览器。
- 开发：`npm start`；仅开服用 `npm run serve`。
- 环境：Node.js 22+，支持 WebGL 的浏览器，游戏无 npm 依赖和构建步骤。
- 固定地址：`http://127.0.0.1:8123/`，重复启动识别同目录服务。
- 核心检查：`npm run verify`。服务运行后执行 `npm run test:browser`。
- 当前证据：[本轮验证](archive/validation/2026-10-24/RESULT.md)（已归档）。

#### 本轮变更

存档默认值与类型归一化提取至 src/core/saveSchema.js，原 progress 公共导出保留。事务提取至 saveTransaction.js，归档、改名、代表作、奖励、断刀、单刀赛事、每日奖励和设置在保存成功后发布状态，并补充失败提示和关键重试入口。

赛事共用展示组件提取至 src/ui/arenaReportParts.js，未改变评分权重、卡牌效果、资源路径和 Three.js 加载顺序。

主冒烟、锻造、正式赛事与缺资源探针共用 tools/lib/browser.mjs 配置，并有失败退出码。其他历史探针仍需检查自身报告，不能仅凭退出码判断。

#### 后续边界

- 本轮不是全面渲染性能验收，历史 GPU 耗时不能代表当前设备。
- 手机尺寸模拟不能代替 Android/iOS 实机；Firefox 和真实移动硬件仍需另测。
- 保留 v2 与 legacy，不按目录名删除有效内核。
- 不自动重做历史已经否定的 shader 优化、图集 mip/padding 或晶体预热闸门方案；需先说明新缺陷及测量依据。
- 多标签页写档锁、跨设备同步尚未实现。
- 大型赛事和渲染模块继续按独立职责、可测收益和兼容性逐步拆分。
