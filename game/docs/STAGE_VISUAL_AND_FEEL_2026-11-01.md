## 一、B1 · 材料与熔炼 ✅ 本轮实现

### 改造前（实测）

真实 Chromium 390×844 截图中，S2「熔炼主工艺」阶段的 `molten_sphere_small`
渲染成**一块黑色钝石**：无发光、无温度提示、无熔液感。玩家无法从画面判断
这是「正在熔化的金属」还是「一块石头」，炉火环节的情绪完全丢失。

### 实现

新增 `src/render/stageHeat.js`（纯数据 + 纯函数）：

- 按工序给出温度语义：S2 `molten`、S3 `hot`、S4 `warm`、S5 `quenching`、S6+ `cold`
- 黑体辐射色阶：暗红 `#5c1a06` → 橙红 `#a82a08` → 橙黄 `#d95a12` → 亮橙黄 `#f0952a` → 近白热 `#ffe6b8`
- S2 缓慢呼吸（周期 2.4s，幅度 ±12%）模拟熔液对流；`reducedMotion` 下改为恒定温度
- 只允许炉内模型（ore / molten / ingot）承载热量；刀身在除淬火外的阶段一律冷钢
- **始终先清零再按需施加**：热量不会泄漏到后续工序、鉴定页或收藏

### 实测结果（真实 Chromium 390×844）

| 阶段 | 模型 | emissive | intensity |
|---|---|---|---|
| S1 | ore_small | `000000` | 0 |
| S2 | molten_sphere_small | **`d95a12`** | **0.62** |
| S4 | knife_straight | `000000` | 0 |

截图确认：S2 熔融球从黑色钝石变为**炽热橙红、带熔液流动层次**的金属球。

### 过程中发现并修复的两个时序陷阱

1. **emissive 被 applySkin 覆盖**：若在 `applySkin` 之前施加，材质写入会把
   emissive 重置回黑色。现在改为在 `applyBladeSkin` 之后施加，并在每次
   延迟视觉重放后再施加一次。
2. **配方表被编辑截断**：一度丢失 S8–S10 三档。测试现在断言十个阶段全部存在，
   避免漏档静默通过。

## 二、B3 · 淬火 ✅ 本轮实现

### 改造前（实测）

S5 淬火阶段使用 `warm` / 0.10 的极弱发光，在浅色摄影棚背景上**读不出任何温度**。
但真实淬火是把**通红刀身插入冷却液**——入液那一刻的炽热是这一步的核心视觉。

### 实现

- S5 改为 `red` / **0.42**，刀身呈明显暗红炽热
- `canCarryHeat(modelId, stageId)` 显式区分：**只有 S5 允许刀具模型自发光**，
  S1–S4 与 S6–S10 的刀身保持冷钢，避免整把刀变成发光棒、保证收藏页准确

### 实测结果（真实 Chromium 390×844）

| 阶段 | 模型 | emissive | intensity |
|---|---|---|---|
| S4 | knife_straight | `000000` | 0 |
| S5 | knife_straight | **`a82a08`** | **0.42** |

截图确认：S5 刀身呈暗红炽热的钢坯状态，一眼可辨「这是刚出炉的高温刀身」。

## 三、B6 · 装配与鉴定 ◐ 既有实现已达标（本轮仅核查）

### 核查方法

推进到 S8 选卡阶段，逐张预览三张刀柄候选，采样两个区域的平均色：

- 刀身带：画布高度 12%–42%
- 刀柄带：画布高度 62%–82%

### 实测结果（真实 Chromium 390×844，`b6-evidence/b6-report.json`）

| 刀柄卡 | handle.metalId | 刀柄 R,G,B | 刀柄暖度 (R−B) | 刀身暖度 |
|---|---|---|---|---|
| 旧木柄 S8_12 | `h_aged_wood` | 127.0, 119.2, 110.3 | **+16.7** 暖棕 | −64.7 |
| 云脉石柄 S8_11 | `h_cloud_stone` | 154.8, 163.9, 176.5 | **−21.7** 冷灰 | −64.7 |
| 温木柄 S8_01 | `h_warm_wood` | 148.3, 138.7, 125.7 | **+22.5** 暖棕 | −64.7 |

**结论**：三种刀柄产生显著不同的材质（暖棕 / 冷灰 / 更深暖棕），而刀身区域
三张卡完全一致（−64.7）——证明**只有刀柄在变，材质对比成立**。
截图亦可肉眼确认：旧木柄呈暖灰褐、云脉石柄呈冷白灰。

**这一项本轮没有改动任何代码**。第一轮我以为「刀柄没变化」，是因为采样时
用了「只放行偏蓝像素」的过滤条件，把木柄的棕色筛掉了——那是测量方法的缺陷，
不是游戏的缺陷。数据链（`cardWrites.js` → `handle.metalId` → `handleMaskGate`
→ `uHandleTint`）本来就是完整可用的。

### 仍未做的部分

装配**过程演出**（装配动画、结构反馈）未实现；本轮只确认材质对比成立。

## 五、B4 / C1 · 刀具 PBR ❌ 未达成（四次尝试均被实测否决）

用户明确要求「材质不重写但要优化」，因此只在渲染层尝试，不动 218 卡与材质表。
**两次尝试都被真实数据证否，已完整回退**：

### 尝试一：接线 `specularIntensity`

发现材质表 25 种材质**全部**声明了 `specularIntensity`（0.62–1.00），但全仓
没有任何一处把它写到 three 的 `material.specularIntensity`——`toPhysicalMaterial`
里硬编码为 `1`，`bladeViewer` 两条应用路径也从未设置。

接线后 `specularIntensity` 确实从 1 变成材质表的值（实测 M02 = 0.92），**但
A/B 像素差为 0**：刀身走 bladeSkin 自定义 shader，只消费 `roughnessFactor`，
不读 three 的 specular 通道。已回退。

### 尝试二：调整 `STAGE_ROUGH_GAIN` 曲线

把 S5–S9 的粗糙度曲线从 `[1,1,1,.72,.46,.52,.34,.36,.27]` 改为更平缓的
`[1,1,1,.88,.68,.60,.46,.40,.34]`（保留缎面刀身、把镜面交给纹理层）。

**用极端值验证灵敏度**：把整条曲线改成 `3.00`（粗糙度 ×3），真实 Chromium
画面**完全不变**（对比度 147.3 → 147.3）。原因是 S4 阶段 `reachedStages = 0`，
曲线索引落在兜底路径上，该参数在此阶段不参与计算。已回退。

### 尝试三：深入 shader 与贴图，定位蓝色来源

不再猜参数，改为直接读运行时真实数据：

| 探针 | 实测值 | 含义 |
|---|---|---|
| 材质类型 | `MeshPhysicalMaterial` | S4 阶段 **bladeSkin hook 尚未挂载**（`hasHooks: false`） |
| `material.color` | `ffffff` | 材质本身是**白色**，不含任何色相 |
| `map` / `mapColorSpace` | `true` / `srgb` | 颜色来自 GLB 自带的 baseColor 贴图 |
| **贴图平均色** | **81.9, 82.0, 81.8** | 贴图本身是**中性灰**，不是蓝色 |
| `metalness` / `roughness` | 0.86 / 0.216 | 高金属度 + 低粗糙度 |
| `envMap` / `envMapIntensity` | `true` / 0.884 | 存在环境反射 |
| 环境光 | `hasEnvironment: true`，`environmentIntensity: 0.55` | 白色 HDR 摄影棚 |
| 四盏灯 | 2 向光 + 1 背光 + 半球光 | 全部冷白／近白 |

**结论**：贴图是中性灰、材质色是纯白，那么刀身呈现的**饱和蓝色只能来自环境反射**
（metalness 0.86 的金属，漫反射几乎为零，像镜子一样反射周围）。

### 尝试四：直接改 envMapIntensity / metalness 验证

为确认这一判断，在运行时把 `envMapIntensity` 设为 0，以及把 `metalness` 降到 0.1、
`roughness` 升到 0.6，各采样一次：

| 条件 | R, G, B | 暖度 |
|---|---|---|
| 基线 | 93.5, 144.6, 172.3 | −78.8 |
| `envMapIntensity = 0` | 93.5, 144.6, 172.3 | **−78.8（无变化）** |
| `metalness=0.1, roughness=0.6` | 93.5, 144.6, 172.3 | **−78.8（无变化）** |

逐字符完全相同的读数说明**这些属性在每次 rAF 被 `applySkin` 回写**，运行时直接
改无法用于验证。这是既有架构的「可见材质唯一写入路径」设计（`applySkin` 是
唯一 owner 边界），不是缺陷，但它意味着**任何绕过该路径的调参都无法生效**。

### 结论：本轮未达成，且已到达尝试上限

按项目规则「同一故障最多连续修复 3 次」，本项已用完 3 次尝试（specularIntensity
接线、roughness 曲线、运行时属性直改），**全部被真实数据证否**，均已完整回退，
工作区无残留改动。

**我确认为真的结论**：
1. 刀身的颜色由**环境反射**主导，而环境是白色 HDR 摄影棚 → 反射呈冷色；
2. 贴图是中性灰、材质色是纯白，**改材质参数不会改变这个物理链路**；
3. 在不重写材质体系（用户明确要求）且不替换环境贴图的前提下，本轮找不到
   能真正提升刀身金属质感的渲染层杠杆。

**下一轮的正确方向**（需要用户先决定，不在本轮擅自执行）：
- 换一套更中性的摄影棚 HDR（会改变全场景氛围，属视觉体系级改动）；
- 或在 `applySkin` 的**正式写入路径**里加入按工序的金属质感曲线（需要改
  `bladeViewer` 的材质写入逻辑，风险高于本轮所有改动）；
- 或重新审视 GLB 贴图与 PBR 烘焙流程（属材质专项）。

**不把无效实验算作已优化。** 本项如实标记为未达成。
